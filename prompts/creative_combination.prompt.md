# 創造的組み合わせプロンプト

既存の概念、技術、デザインパターンを新しい視点で組み合わせることで、独創的で効率的な解決策を生み出してください。完全に新しいものを作り出すのではなく、既知の要素を革新的に組み合わせることで、予想外の価値を創造します。

## 実行手順

### 1. 既存パターンの列挙

まず、関連する既存の概念や手法を広く収集します：

**技術パターンの収集**:

- デザインパターン（GoF、エンタープライズパターンなど）
- アーキテクチャパターン（MVC、MVVM、Clean Architecture など）
- データ構造とアルゴリズム
- プログラミングパラダイム（OOP、FP、リアクティブなど）

**ドメイン知識の活用**:

- 業界標準のアプローチ
- 競合他社の実装方法
- オープンソースプロジェクトでの解決策
- 学術研究での最新の知見

**社内資産の棚卸し**:

- 過去のプロジェクトでの実装
- 再利用可能なライブラリやモジュール
- チームメンバーの専門知識
- ドキュメントやナレッジベース

**ツールとフレームワーク**:

- 利用可能な技術スタック
- サードパーティライブラリ
- クラウドサービス
- 開発ツールやCI/CD

### 2. 類似問題の調査

同様の課題がどのように解決されてきたかを調査します：

**問題の抽象化**:

- 具体的な問題を一般化する
- 本質的な課題は何か？
- どのカテゴリの問題か？（パフォーマンス、スケーラビリティ、保守性など）

**類似ドメインの探索**:

- 他の業界での解決策（金融、医療、ECなど）
- 規模の異なるプロジェクトでのアプローチ
- 異なる技術スタックでの実装
- 歴史的な解決方法の進化

**ケーススタディの分析**:

- 成功事例の詳細な分析
- 失敗事例からの学び
- トレードオフの理解
- 適用条件の把握

### 3. 異分野からの転用

全く異なる分野からのアイデアを取り入れます：

**他の技術領域からの借用**:

- フロントエンドの手法をバックエンドに（またはその逆）
- モバイルアプリの手法をWebに
- ゲーム開発の技術を業務アプリに
- 組み込みシステムの制約下での最適化手法

**物理世界からの類推**:

- 自然界のパターン（フラクタル、ネットワーク構造）
- 工学的な原則（冗長性、フェイルセーフ）
- 生物学的なメカニズム（進化的アルゴリズム、免疫システム）
- 物理法則の応用（エントロピー、平衡状態）

**ビジネスやマネジメントの原則**:

- リーンスタートアップの原則をアーキテクチャに
- アジャイル開発の考え方をデータ処理に
- プロジェクト管理手法をビルドパイプラインに
- マーケティングの手法をAPI設計に

### 4. 組み合わせの試行

収集した要素を様々な形で組み合わせます：

**マトリックス分析**:

- 要素Aと要素Bを組み合わせたら？
- 複数の要素を同時に適用したら？
- 要素を逆転させたら？（通常とは逆のアプローチ）

**制約の変更**:

- 制約を緩めたらどうなるか？
- 逆に制約を厳しくしたら？
- 異なる制約を課したら？

**段階的な統合**:

- 小さな組み合わせから始める
- プロトタイプでの検証
- 段階的に複雑さを追加
- フィードバックに基づく調整

**逆説的なアプローチ**:

- 通常とは逆のことをしたらどうなるか？
- 問題を解決するのではなく、問題を避ける方法は？
- 複雑さを追加するのではなく、削減したら？

### 5. 検証と洗練

組み合わせたアイデアを評価し、実用的な形に磨き上げます：

**実現可能性の評価**:

- 技術的に実装可能か？
- パフォーマンス要件を満たせるか？
- 既存システムとの統合は可能か？
- チームのスキルセットで実現できるか？

**プロトタイプの作成**:

- 最小限の実装で概念を検証
- ベンチマークでの性能測定
- ユーザビリティテスト
- セキュリティレビュー

**反復的な改善**:

- フィードバックの収集
- 問題点の特定と修正
- 最適化とチューニング
- ドキュメント化

## 期待される成果

- **独創的な解決策**: 従来の方法では思いつかない革新的なアプローチ
- **効率的な設計**: 既存の実証済みの要素を組み合わせることで、信頼性とイノベーションを両立
- **競争優位性**: 独自の技術的アプローチによる差別化
- **学習の加速**: 異分野からの知識吸収により、チームの能力が向上
- **コストの最適化**: 既存資産の活用により、開発コストを削減
- **柔軟性の向上**: 多様なアプローチを知ることで、状況に応じた選択が可能に

## 注意事項

- **複雑さの管理**: 組み合わせすぎて複雑になりすぎないよう注意
- **過度な抽象化を避ける**: 実用性を失わない範囲で
- **既存の知見を無視しない**: 車輪の再発明にならないよう、既存のベストプラクティスも尊重
- **チームの理解**: 独創的すぎて他のメンバーが理解できないものは避ける
- **保守性の考慮**: 長期的なメンテナンスを考慮した設計
- **段階的な導入**: いきなり全面的に適用するのではなく、小さく始める
- **失敗の許容**: すべての組み合わせが成功するわけではない。実験的なアプローチを許容する文化
